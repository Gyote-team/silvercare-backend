# 방문 관리 브라우저 확인 절차

## 준비

- 백엔드 PR #38과 프론트 PR #12의 최신 브랜치를 실행한다.
- 서로 ACTIVE로 연결된 개인과 보호자, 수정 가능한 같은 방문을 준비한다.
- 일반 창과 시크릿 창 또는 서로 다른 브라우저를 사용한다. 같은 브라우저의 일반 탭 두 개는 로그인 쿠키를 공유하므로 계정을 분리하는 데 사용할 수 없다.
- 창 A는 개인, 창 B는 해당 개인과 연결된 보호자로 로그인한다. 보호자는 관리할 개인을 선택한다.
- 두 창에서 같은 방문 상세를 연 뒤 모두 방문 수정을 누른다. 두 번째 창은 첫 번째 저장 후 새로고침하지 않는다.

## 개인 먼저 저장 → 보호자 충돌

1. A에서 메모를 `개인 먼저 저장한 내용`으로 바꾸고 수정 저장을 누른다.
2. A에 수정 성공이 표시되는지 확인한다.
3. B에서 메모를 다른 내용으로 바꾸고 수정 저장을 누른다.
4. B의 PUT 요청이 HTTP 409, code GLOBAL_004인지 확인한다(브라우저 개발자 도구 Network).
5. B에 `다른 곳에서 방문 정보가 변경되어 현재 화면이 오래됐어요. 방문을 다시 불러온 뒤 수정해 주세요.`와 방문 다시 불러오기 버튼이 표시돼야 한다.
6. B의 수정 저장은 비활성화되며, 다시 불러오기를 누르면 작성 내용 폐기 확인 후 A가 저장한 메모가 표시돼야 한다.

## 보호자 먼저 저장 → 개인 충돌

1. 양쪽에서 최신 방문을 다시 불러오고 다시 수정을 연다.
2. 이번에는 B가 먼저 다른 메모를 저장한다.
3. A가 이전 화면의 내용으로 저장하면 같은 409 안내가 표시돼야 한다.
4. A에서 다시 불러오면 B의 메모가 유지돼야 한다. 최신 버전으로 다시 수정하는 것은 정상 저장돼야 한다.

## 상태 구분 및 문서 복귀

1. 예정·완료가 기본 선택되어 취소된 방문이 표시되지 않는지 확인한다.
2. 전체에서는 모든 상태, 방문 예정·방문 완료·취소된 방문에서는 해당 상태만 표시되는지 확인한다. 취소된 카드는 회색 배경·점선 테두리·병원명 취소선으로 구분된다.
3. 연결 문서가 있는 방문 상세에서 병원 서류 보기를 누른다.
4. AI 설명 대기 화면에도 방문 상세로 돌아가기가 표시되는지 확인한다.
5. 해당 링크를 누르면 같은 방문 상세와 연결 자료가 표시돼야 한다. 문서함에서 직접 연 문서는 기존 문서함 복귀를 유지한다.

## 실행 결과 (2026-10-15)

전용 로컬 PostgreSQL DB에서 김순자(개인)와 박지훈(연결된 보호자)로 수행했다. 사용 가능한 자동화 브라우저가 하나여서 localhost:3000과 127.0.0.1:3001을 각각 localhost:8081과 127.0.0.1:8081 API에 연결해 로그인 쿠키를 분리했다. 두 창의 로그인 역할과 대상 방문이 같은지 화면에서 확인했다.

- 개인 먼저 저장 후 보호자 저장: 오래된 화면 안내 및 저장 차단, 다시 불러온 개인의 메모 유지 확인.
- 보호자 먼저 저장 후 개인 저장: 오래된 화면 안내 및 저장 차단, 다시 불러온 보호자의 메모 유지 확인.
- 실제 서버의 버전 충돌 HTTP 계약은 VisitApiIntegrationTest에서도 409/GLOBAL_004로 검증한다.
- 연결 문서의 AI 설명 대기 화면에서 같은 방문 상세로 복귀 확인.
- 기본 예정·완료 목록, 예정 전용, 완료 전용, 취소 전용, 전체 목록을 브라우저에서 각각 확인. 취소 카드의 회색·점선·취소선 구분 확인.
